关键特性：即时可见

每个节点的输出在该节点执行完成时立即写入变量池，后续节点可以引用。不需要"等待工作流结束后才可用"。

Dify 用不同的 node_id 前缀区分变量来源

环境变量 + 对话变量

env.* — 环境变量

在 Dify 应用设置 → 环境变量中配置。适合存储 API Key、配置项等不硬编码的值。

# 使用方式 env.API_KEY env.BASE_URL env.MODEL_NAME

优势：密钥不暴露在工作流 YAML 中，环境切换只需改配置

conversation.* — 对话变量

仅在 Chat 模式中使用，跨对话轮次持久化。

# 适合存储 conversation.user_preference # 用户偏好 conversation.last_topic # 上一轮话题 conversation.collected_info # 收集的信息

典型场景：多轮表单填写、偏好学习、上下文追踪

写变量：VariableAssigner

基本用法

相当于代码中的 = 赋值操作

# YAML 配置 变量: processed_text 值: {{llm_node.text}} 类型: string
覆盖语义

如果变量已存在，赋值节点会覆盖它。后续节点看到的是最新值。

# 第一次：写入 score = 85 变量: score → score = 85 # 第二次：覆盖为 score = 92 变量: score → score = 92
常见错误

变量名冲突 — 两个 VariableAssigner 写入同一变量名，后执行覆盖前一个

迭代内部写入 — 在迭代内写入的变量无法被外部引用（作用域隔离）

变量作用域：迭代和循环隔离

主工作流作用域

变量：sys.*, env.*, conversation.*, 各节点输出

迭代 / 循环子作用域

内部变量对外部不可见

外部变量对内部只读

错误示范 # 迭代内赋值 → 外部引用为空 [Start] → [Iteration] └─ [VariableAssigner: score = 100] → [LLM: 引用 {{score}}] ← score 在迭代内部！ 正确做法

迭代/循环的输出字段是唯一对外暴露的数据通道。走输出，不走赋值器。

迭代/循环的特殊变量

迭代 (Iteration)
{{迭代节点.item}}当前迭代元素
{{迭代节点.index}}当前索引（从 0 开始）
{{迭代节点.output}}迭代结束后输出数组
循环 (Loop)
{{循环节点.index}}当前循环索引
{{循环节点.item}}当前循环元素
{{循环节点.output}}循环结束后输出数组
典型用法
# 迭代：批量处理文本列表 {% for item in texts %} 处理 {{loop_node.item}} # 每次循环拿当前元素 {% endfor %} # 循环出口：收集所有结果 {{loop_node.output}} # → [result1, result2, result3, ...]

类型不匹配问题

正确匹配
# IF 条件：sys.query is "退款" sys.query → string "我要退款" "退款" → string string vs string → 匹配
类型不匹配
# IF 条件：llm.usage > 50 llm.usage → object {prompt_tokens,...} 50 → number object vs number → 不匹配
解决方案：Code 节点提取字段
# BEFORE（类型不匹配） IF 条件: llm.usage > 50 ❌ object vs number # AFTER（Code 节点桥接） [LLM] → [Code: 提取 total_tokens] → [IF: total_tokens > 50] def main(usage: object): return {"total_tokens": usage["total_tokens"]} ✓ number

变量问题排查 4 问

问题 1：变量选择器找不到上游节点

原因：没有边连接 — 没有边 = 引擎认为它们没有依赖关系
修复：确保两个节点之间有箭头（边）连接

问题 2：引用值为空 — 4 项检查

1. 上游节点是否执行了？（看运行日志）
2. 引用的字段名是否正确？（区分大小写）
3. 是否在迭代/循环内部定义的变量？（作用域隔离）
4. 上游节点是否设置了"失败时继续"但实际失败了？

问题 3：模板渲染不对

{{检索.result}} — array[object] 直接拼接

{% for item in 检索.result %}{{ item.content }}{% endfor %} — 遍历数组取字段

问题 4：赋值器写入后仍为空 — 3 项检查

1. 赋值器执行顺序 — 是否在引用它的节点之前执行？
2. 是否被 IF-ELSE 跳过？（赋值器在某个分支中但走了另一个分支）
3. 变量名没有冲突
