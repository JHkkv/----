Code 与 HTTP 并行 → 汇聚到 LLM

class WorkflowGraphTopology:
    def is_upstream(
        self,
        node_a: str,
        node_b: str
    ) -> bool:
        """检查 node_a 是否在
           node_b 的上游"""
        if node_a == node_b:
            return True
        for edge in self.edges:
            if edge.source == node_a:
                if self.is_upstream(
                    edge.target, node_b
                ):
                    return True
        return False

变量池代码 — add_variables_to_pool()

class VariablePool:
    def add_variables_to_pool(
        self,
        node_id: str,
        outputs: dict
    ) -> None:
        """将节点输出写入变量池

        参数:
            node_id: 节点 ID（如 "17200001"）
            outputs: 节点输出字典
                    {"text": "...",
                     "usage": {...}}
        """
        for field_name, value in outputs.items():
            key = (node_id, field_name)
            self._pool[key] = value

    def get_variable(
        self,
        node_id: str,
        field_name: str
    ) -> Any:
        """读取变量"""
        return self._pool.get(
            (node_id, field_name)
        )

开始搭建前必知的 8 件事

01
Start 节点决定输入
定义工作流接收哪些字段，相当于函数签名
02
End 节点决定输出
只有 End 节点标记的字段才会作为 API 返回值
03
变量引用必须依赖边
节点 A 要引用节点 B 的输出，必须先连线 A ← B
04
迭代/循环创建子作用域
内部变量独立，外部无法直接访问迭代内的输出
05
分支按条件选择执行
IF-ELSE 条件分支只执行匹配的路径，其余跳过
06
LLM 节点必须配模型
选择 LLM 提供方（OpenAI / Claude / 本地模型）并配置参数
07
Code 节点沙箱限制
仅 Python/JS，无网络访问（除 HTTP 请求库），超时限制
08
发布后才能被 API 调用
画布中的修改必须"发布"后才会在 API 中生效
