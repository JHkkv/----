# 播客制作 Skill — 架构设计文档

> 本架构源自 2026-08-04「经济阵痛期」双人播客实战复盘。目标：把"多 Agent 内容流水线"固化为可复用能力，用户只需给主题，即可产出合规、有钩子、可交付的双人播客台本。

## 一、设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 安装位置 | 用户级 `C:\Users\ASUS\.claude\skills\` | 内容工作流跨项目复用（公众号/AI经济/求职简历） |
| 执行模式 | **阶段确认式** | 每阶段产出后暂停给用户确认，控制权留在用户；符合用户"先询问再执行"偏好 |
| 角色形态 | 4 个子 Agent（调研/资料/优化/审查） | 与实战完全一致，各自职责单一、Prompt 可复用 |
| 交付物 | Markdown + officecli docx 双格式 | 实战已验证；docx 用 officecli 生成 |
| 免责/合规 | 内嵌合规矩阵 + 事实核验边界 | 财经内容红线多，合规必须前置 |
| 质量红线 | 数据守真（可锚定来源、不编造）+ 无敏感词 | 源自实战审查发现 |

## 三、状态机（阶段确认式）

```
[触发] 用户给出播客主题 + 平台 + 时长
   │
   ▼
P1 需求澄清 ── AskUserQuestion：角色设定 / 内容侧重(可多选) / 交付物
   │                    └→ 用户不选则用默认（打工人×乙 / 全板块 / MD+docx）
   ▼
P2 调研 + 资料（2 Agent 并行）
   │  ├─ 市场调研Agent：话题热度/受众焦虑/爆款钩子/平台合规红线
   │  └─ 资料收集Agent：数据事实+来源+口径边界
   │
   ▼  ⚠ 确认点 A：汇总调研结论 → 用户确认方向
P3 台本初稿（主 Agent 编写）
   │
   ▼  ⚠ 确认点 B：初稿 → 用户确认后进入优化
P4 优化 + 审查（2 Agent 并行）
   │  ├─ 文案优化Agent：节奏/钩子/金句/情绪曲线/口语化
   │  └─ 内容审查Agent：合规红线逐条查 + 事实核验
   │
   ▼  ⚠ 确认点 C：优化稿+审查报告 → 用户拍板
P5 合成终稿（主 Agent 合并裁决）
   │     保留有据数据+锚定来源 / 删除越界项 / 模糊敏感项
   ▼
P6 交付（MD + officecli 转 docx）
```

**阶段确认点：A（调研方向）、B（初稿）、C（优化+审查结果）三处暂停。**
用户可通过控制指令跳过任意确认点（快速模式）。

## 四、子 Agent 职责

| Agent | 职责 | 输出 |
|-------|------|------|
| market-researcher | 话题热度、受众画像、爆款结构、平台合规红线 | 调研报告（含钩子句式） |
| fact-collector | 四方向数据事实、来源、口径边界、禁引项 | 事实弹药库 |
| copy-polisher | 节奏/钩子/金句/情绪曲线/口语化/画面感 | 优化后台本 + 修改说明 |
| content-reviewer | 合规红线逐条查 + 事实核验 + 最终裁定 | 审查报告（分级清单） |

## 五、合规红线（预置，来自实战）

封禁级：具体理财产品推荐 / 收益承诺 / 稳赚暗示 / 编造数据 / 恶意唱衰
限流级：绝对化用语 / 恐慌渲染 / 特定职业负面 / 假设性裁员对话 / 隐私诱导 CTA
处理原则：**有据数据保留+锚定来源，越界项删除，敏感项模糊化**

## 六、质量红线

- 数据不编造：找不到来源就模糊化或删
- 全文无绝对化用语、无高危词（躺平/暴雷/崩盘）
- 结尾必须给希望/行动方案（情绪 V 字型）
- 金句 ≥ 5 处可截图
- 每个 Agent Prompt 末尾带免责声明

## 七、交付物模板（docx 结构）

信息卡 → 合规说明+来源表 → 最终台本（H2分段）→ 分镜/字幕速查表 → 金句速览 → 发布前自查清单 → 页脚页码
