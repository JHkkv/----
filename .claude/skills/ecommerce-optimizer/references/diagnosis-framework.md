# 产品诊断框架（Diagnosis Framework）

> product-diagnostician Agent 的诊断依据。7 维度系统诊断 + 评分标准 + 诊断问卷。
> 只诊断，不给优化建议（优化是 P6-P7 的事）。

## 一、7 维度总览

| # | 维度 | 核心问题 | 关键指标 |
|---|------|---------|---------|
| 1 | 产品力 | 产品本身够不够打 | 品质/功能/差异化/供应链 |
| 2 | 价格力 | 定价是否合理 | 价格带位置/性价比/利润空间 |
| 3 | 视觉力 | 页面是否吸引人 | 主图/详情页/视频/风格 |
| 4 | 服务力 | 服务是否留人 | 评分/评价内容/客服/退换货 |
| 5 | 内容力 | 站外有没有声量 | 种草/短视频/直播/达人 |
| 6 | 投放力 | 广告投得对不对 | 投放现状/关键词/ROI |
| 7 | 流量力 | 流量够不够多 | 自然流量/搜索排名/活动资源 |

## 二、评分标准（1-5 分）

### 维度 1：产品力

| 分数 | 标准 |
|------|------|
| 5 | 品质稳定，功能/设计有差异化，供应链强 |
| 4 | 品质好，有小差异点，供应链正常 |
| 3 | 品质合格，无突出差异，供应链一般 |
| 2 | 品质波动，功能同质化，供应链紧张 |
| 1 | 品质问题多，明显同质化，供货不稳 |

### 维度 2：价格力

| 分数 | 标准 |
|------|------|
| 5 | 价格带优势明显，利润空间健康 |
| 4 | 定价合理，与价值匹配 |
| 3 | 与主流持平，无价格优势也无劣势 |
| 2 | 偏高，性价比不足 |
| 1 | 明显偏离市场价位 |

### 维度 3：视觉力

| 分数 | 标准 |
|------|------|
| 5 | 主图有记忆点，详情页结构佳，有视频 |
| 4 | 视觉规范，主图清晰，详情页完整 |
| 3 | 中规中矩，无大错也无亮点 |
| 2 | 主图杂乱，详情页信息乱 |
| 1 | 视觉明显落后于竞品 |

### 维度 4：服务力

| 分数 | 标准 |
|------|------|
| 5 | 高分（4.8+），好评率高，客服响应快 |
| 4 | 评分良好，评价以正面为主 |
| 3 | 评分一般，有零星差评 |
| 2 | 评分偏低，差评集中某类问题 |
| 1 | 低分，差评多且未处理 |

### 维度 5：内容力

| 分数 | 标准 |
|------|------|
| 5 | 内容矩阵丰富（笔记/视频/直播/达人） |
| 4 | 有稳定的站外内容产出 |
| 3 | 少量内容，不成体系 |
| 2 | 几乎无站外内容 |
| 1 | 无任何站外曝光 |

### 维度 6：投放力

| 分数 | 标准 |
|------|------|
| 5 | 投放系统化，关键词覆盖广，ROI 健康 |
| 4 | 有投放，覆盖部分关键词 |
| 3 | 投放零散，无策略 |
| 2 | 基本无投放 |
| 1 | 无投放能力，流量全靠自然 |

### 维度 7：流量力

| 分数 | 标准 |
|------|------|
| 5 | 搜索排名靠前，自然流量稳定，有活动资源 |
| 4 | 有稳定自然流量，排名中上 |
| 3 | 流量依赖单一来源，不稳定 |
| 2 | 流量少，来源单一 |
| 1 | 几乎无自然流量 |

## 三、评分规则

1. **必须有依据**：每个评分附评分依据（数据/观察/商家提供）。
2. **标注可信度**：每维度评分标注数据可信度 `[A/B/C]`。
3. **数据不足标注**：商家未提供数据的维度，标注"数据不足，基于有限信息推测（C级）"，评分打"待定"或用区间。
4. **交叉影响**：诊断时注意维度间关联（如"投放力低"常与"流量力低"相关，但原因不同）。

## 四、TOP3 问题识别

从 7 维度中选出影响最大的 3 个问题：

| 判定维度 | 说明 |
|---------|------|
| 影响面 | 该问题影响多少流量/转化/复购 |
| 紧急程度 | 高（正在流失）/ 中（持续恶化）/ 低（隐患） |
| 修复难度 | 低（1-2 天）/ 中（1-2 周）/ 高（1 月+） |
| 与对标差距 | 与该维度 4 分以上对标对象的差距 |

**TOP3 选择逻辑**：按"影响面 × 紧急程度"排序，优先选影响大且紧急的。

## 五、诊断问卷（P1 阶段可向商家提问）

### 5.1 基础信息

1. 主营品类和核心单品是什么？
2. 店铺层级/规模（月销多少单）？
3. 客单价大概多少？
4. 上架多久了？主要流量来源？

### 5.2 经营数据（B 级，商家提供）

5. 转化率（浏览→下单）大概多少？
6. 流量结构（自然搜索/付费/活动/私域各占比）？
7. 好评率和主要差评类型？
8. 复购率如何？老客占比？

### 5.3 问题感知

9. 你觉得当前最大问题是什么？（销量下滑/转化率低/流量不足/竞品打压/评分低）
10. 什么时候开始感觉到问题的？
11. 之前尝试过哪些改进？结果如何？

### 5.4 资源

12. 是否有运营团队/广告预算/供应链支持？
13. 愿意为改版投入多少预算和时间？

## 六、诊断报告输出格式

```markdown
## 产品诊断报告

> 诊断对象：{品类/单品} | 平台：{平台} | 诊断日期：{日期}

### 一、诊断评分矩阵
| 维度 | 评分(1-5) | 评分依据 | 数据可信度 |
|------|----------|---------|-----------|
| 产品力 | 3 | 品质合格，无突出差异 | B+C |
| ... | ... | ... | ... |

### 二、问题雷达图（文字版）
[高分的维度 + 低分的维度，用文字描述形状]

### 三、TOP3 核心问题
### 问题1：[名称]
- 影响面：[...]
- 紧急程度：[高/中/低]
- 修复难度：[低/中/高]
- 与对标差距：[...]

### 四、优先级排序建议
[按影响面×紧急程度排序，附逻辑说明]

### 五、数据缺口说明
[哪些维度数据不足，降级为 C 级]
```

## 七、诊断确认（确认点A）

诊断报告产出后，主 Agent 向商家展示摘要（评分矩阵 + TOP3 问题），请商家确认"符合实际情况"或修正。

- 商家修正某维度 → 按补充信息重评该维度，重出摘要
- 商家确认 → 进入 P3
