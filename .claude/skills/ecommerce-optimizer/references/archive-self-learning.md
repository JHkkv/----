# 归档自学习协议（Archive & Self-Learning）

> 需求：**每次使用后产生归档文件，自动上传到本人 GitHub 私人仓库，供 Skill 自动学习调整。**
>
> 两个硬约束：
> 1. **脱敏**：归档只存方法论经验 + 脱敏后的行业级数据，不存商家身份/经营数字/真实 URL。
> 2. **私有**：只推送到用户本人的私人仓库（SSH: `git@github.com:JHkkv/-.git`），不允许除本人外查看和修改。

## 一、归档内容（脱敏）

### 1.1 归档模板

归档文件命名：`archive/{平台}/{YYYY-MM-DD}-{品类脱敏}.md`

```markdown
---
type: ecommerce-case
platform: {平台}
category: {品类（泛化，如"家居收纳"）}
price-band: {价格带泛化，如"¥50-100"}
pain-point: {痛点类型，如"转化率低"}
gate-result: {通过|拒绝}
data-availability: {A级X项/B级Y项/C级Z项}
tags: [品类, 平台, 痛点, 策略]
---

# 案例归档：{品类} {平台} {痛点}

> 归档日期：{日期}（脱敏，无商家身份/无经营数字/无URL）

## 一、诊断要点（脱敏）
- 7 维度评分：{产品力X/价格力X/...}
- TOP3 问题类型：{如：视觉力低/投放力低/流量力低}

## 二、对标发现（行业级）
- 对标对象特征：{如：头部主图都用场景化风格}
- 有效策略：{如：主图改场景化+详情页加信任区}
- 无效策略：{如：单纯降价的低价策略在该品类无效}

## 三、确认门记录
- GATE-1：{商家回答质量摘要}
- GATE-2：{通过/拒绝}
- 拒绝模式（如有）：{如：商家拒绝提供成本结构 → R5}

## 四、踩坑经验
1. {踩坑点 1}：{描述}
2. ...

## 五、有效策略（可复用）
1. {策略 1}：{适用场景 + 预期 + 可信度}
2. ...

## 六、数据可得性
- 拿得到：{如：公开榜单/竞品页}
- 拿不到：{如：后台转化率/付费工具数据}
```

### 1.2 脱敏规则（红线）

**归档文件严禁出现：**

| 类别 | 示例 |
|------|------|
| 商家身份 | 店铺名、商家名、联系人、联系方式 |
| 具体经营数字 | 精确销量、精确 GMV、成本结构、利润率 |
| 真实 URL | 商品链接、店铺链接、截图中的 URL |
| 本机路径 | `C:/Users/`、盘符绝对路径 |
| 具体人名/隐私 | 收货人信息、评价中可识别用户的信息 |

**泛化处理示例：**

| 原始信息 | 归档写法 |
|---------|---------|
| 月销 245 单 | "月销数百单" 或 "低量级" |
| 客单价 ¥87 | "价格带 ¥50-100" |
| 转化率 1.2% | "转化率偏低（低个位数）" |
| 店铺"XX家居旗舰店" | "该品类中小型商家" |
| 竞品链接 https://... | "平台头部商品" |

### 1.3 自动脱敏流程

```
交付完成（P9）
   │
   ▼
P10.1 生成脱敏案例（按模板，逐字段泛化）
   │
   ▼
P10.2 敏感模式扫描（scripts/archive-push.sh 或人工复核）
   │  扫描：手机号/邮箱/姓名/URL/本机路径/具体数字
   │  命中 → 泛化修正 → 重扫
   ▼
P10.3 写入本地归档镜像 archive/{平台}/{文件名}
   │
   ▼
P10.4 git commit + push 私人仓库
   │
   ▼
P10.5 推送后远端复核（拉取远端文件再扫一遍）
   ▼
P10.6 更新自学习索引
```

### 2.2 初始化（一次性）


> 若 archive/ 已有内容或 clone 失败，改用配置方式（见第五节），不要强推。

### 2.3 archive/ 不入主 git

- archive/ 目录**不**提交到 `f:\测试工具` 的主 git 仓库（它是独立仓库）。
- 在 `f:\测试工具\.claude\skills\ecommerce-optimizer\` 内对 archive/ 保持独立，主仓库忽略该目录。

## 三、自学习：案例检索 + 经验注入

### 3.1 检索时机

P1 商家档案建立后（P1.5 自学习注入点）。

### 3.2 检索逻辑

按加权匹配从 archive/ 检索相似案例：

```
匹配权重：
  同品类    × 3（最重要）
  同平台    × 2
  同痛点    × 2
  同价格带  × 1
```

取 TOP3 最相似案例，提取：
- **有效策略**（五、有效策略部分）
- **踩坑经验**（四、踩坑经验部分）
- **数据可得性**（六、数据可得性部分）

### 3.3 注入方式

注入到后续 Agent 的 Prompt（product-diagnostician / market-researcher / content-optimizer 等）：

```text
【历史归档相似案例经验】（来自 archive/，脱敏）
- 相似案例1（{平台}/{品类}，{痛点}）：
  有效策略：{...}
  踩坑经验：{...}
  数据可得性：{...}
```

**注入纪律**：
- 只注入**脱敏后的经验**，不注入任何身份/数字。
- 无归档时跳过，不编造历史经验。
- 注入内容标注"历史案例参考，需结合当前商家实际情况验证"。
- 如果归档案例与当前方案冲突（如归档里"降价无效"但当前方案建议低价），标注冲突并说明权衡。

### 3.4 自学习索引（INDEX.md）

```markdown
# 自学习索引

| 归档日期 | 平台 | 品类 | 价格带 | 痛点 | 有效策略要点 | 数据可得性 |
|---------|------|------|--------|------|------------|-----------|
| 2026-08-05 | 淘宝 | 家居收纳 | ¥50-100 | 转化率低 | 主图场景化+详情信任区 | 榜单可得/后台不可得 |
| ... | ... | ... | ... | ... | ... | ... |
```

- 每次归档后更新 INDEX.md。
- P1.5 检索时先读 INDEX.md 定位候选，再读对应归档文件。

## 四、推送流程（scripts/archive-push.sh）

### 4.1 脚本职责

1. 接收归档文件路径参数
2. 扫描敏感模式（手机号/邮箱/URL/本机路径/常见身份字段）
3. 通过 → git add + commit + push
4. 失败/命中敏感 → 输出错误，不 push

### 4.2 脚本位置

`scripts/archive-push.sh`（详见该文件）。

### 4.3 推送规范

```bash
# 手动推送单个归档
bash scripts/archive-push.sh archive/淘宝/2026-08-05-家居收纳.md

# 推送全部新归档
bash scripts/archive-push.sh --all
```

commit 消息：`feat: 案例归档 YYYY-MM-DD {品类}`

## 五、仓库配置

### 5.1 两种配置方式

| 方式 | 说明 |
|------|------|
| 环境变量 | `GITHUB_PRIVATE_REPO`（如 `git@github.com:JHkkv/-.git`），脚本读取 |
| 配置文件 | `archive/repo.config`（内容为仓库地址），脚本读取 |

优先级：环境变量 > 配置文件。

### 5.2 私有性确认

- 推送前确认仓库可见性为 **private**（脚本可调用 `gh repo view --json visibility` 检查，或人工确认）。
- 若仓库非 private，**拒绝推送**并提示用户。

### 5.3 推送安全

- 不硬编码任何凭据在脚本/配置中。
- 使用已配置的 git 凭据（credential helper / SSH key）。
- 推送前必须先通过敏感模式扫描。

## 六、商家拒绝归档的处理

P9 交付后询问一次："是否归档本次案例？"
- 同意 → 走 P10 归档流程
- 拒绝 → 跳过推送；本地**不保留**未脱敏内容（或仅保留用户同意的脱敏记录）
- 归档是默认行为，但商家有否决权

## 七、自学习调整原则

归档数据的用途是**方法论的自我修正**，不是数据囤积：

| 应用 | 说明 |
|------|------|
| 策略积累 | 归档中重复有效的策略 → 提升为"推荐策略" |
| 踩坑积累 | 归档中重复踩坑 → 提升为"预警项" |
| 数据可得性 | 归档显示"某类数据商家普遍拿不到" → 方案设计时主动降级 |
| 拒绝模式 | 归档显示"商家普遍拒绝某类问题" → 优化提问方式或降级该数据依赖 |
| 平台规则 | 归档发现平台新规 → 更新 compliance-rules.md |

**应用纪律**：
- 单一案例不改变规则，重复 2-3 次才调整。
- 自学习结果不能取代当前商家的事实核验——归档经验只是参考输入。
