# 状态机完整定义（P0-P10）

> 本文档是 SKILL.md 状态机的**单一数据源**。所有阶段的状态定义、分支条件、跳过/回溯规则都以本文为准。其他文件引用本文时用状态 ID（P0-P10）。

## 一、状态总览

| 状态 | 名称 | 英文标识 | 是否含确认门 |
|------|------|---------|------------|
| P0 | 权限确认 + 平台选择 | PERMISSION | 权限询问（非强制门） |
| P1 | 商家输入收集 | INPUT | 无 |
| P1.5 | 自学习注入 | SELF-LEARN | 无（读取归档） |
| P2 | 产品诊断 | DIAGNOSIS | 确认点A |
| P3 | 市场调研 + 竞品对标 | RESEARCH | 确认点B |
| P4 | 方案草案 + 商家提问 | DRAFT | **GATE-1（强制）** |
| P5 | 商家回答审查 | REVIEW | **GATE-2（强制）** |
| P6 | 细化执行方案 | PLAN | 确认点C |
| P7 | 内容生产 | PRODUCTION | 确认点D |
| P8 | 配套活动策划 | ACTIVITY | 确认点E |
| P9 | 交付 | DELIVER | 无 |
| P10 | 归档 + 自学习回写 | ARCHIVE | 归档确认 |

## 二、确认门汇总表

| 门编号 | 位置 | 强制等级 | 跳过条件 | 触发行为 |
|--------|------|---------|---------|---------|
| 权限询问 | P0 | 默认 | "不用问了直接用" | 展示权限清单，AskUserQuestion 收授权 |
| 确认点A | P2 后 | 默认确认 | "跳过确认/快速模式" | 展示诊断摘要，商家确认或修正 |
| 确认点B | P3 后 | 默认确认 | "跳过确认/快速模式" | 展示调研发现摘要 + 对标矩阵概览 |
| **GATE-1** | **P4 后** | **强制（不可跳过）** | **无** | 展示方案草案 + 商家问题清单，逐题发问，必须全部回答 |
| **GATE-2** | **P5 后** | **强制（不可跳过）** | **无** | 合理性审查 → 通过/拒绝判定 |
| 确认点C | P6 后 | 默认确认 | "跳过确认/快速模式" | 展示细化方案摘要 |
| 确认点D | P7 后 | 默认确认 | "跳过确认/快速模式" | 展示内容成品 + 审查结果 |
| 确认点E | P8 后 | 默认确认 | "跳过确认/快速模式" | 展示活动方案 |

> **关键设计原则**：GATE-1 和 GATE-2 在任何模式下都不可跳过。即使商家说"快速模式/全自动"，也只跳过 A/B/C/D/E 确认点，GATE-1 和 GATE-2 照常执行。这是本 Skill 的核心——不谄媚迁就用户。

## 三、各阶段详细状态定义

### P0 — PERMISSION（权限确认 + 平台选择）

| 属性 | 说明 |
|------|------|
| 进入条件 | 触发词或隐式触发软确认通过 |
| 退出条件 | (1) 用户确认权限授权（全部或部分）(2) 平台选择确定 (3) 平台配置快照生成 |
| 允许操作 | 展示权限清单、AskUserQuestion 收授权与平台选择、读取 platform-configs.md |
| 禁止操作 | 未经授权调用任何联网工具；开始诊断 |
| 输出物 | 权限授权记录 + 平台配置快照（selectedPlatform + 术语体系 + 榜单源 + 合规差异） |

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 全部授权 | P0 | 记录全部授权，进入平台选择 |
| 部分授权（指定缺哪些） | P0 | 记录授权范围，标记受限能力（对应数据降级为商家提供/领域推理） |
| 不授权联网 | P0 | 标记"数据模式=商家资料+推理"，P3 改为轻量调研 |
| 选平台：淘宝/天猫/拼多多/抖音/亚马逊/其他 | P0 | 读取平台配置，生成快照，进入 P1 |
| 未明确平台 | P0 | 询问品类后推定（如"服装"→ 多平台可套用），标注推定 |
| "跳过权限" | P0 | 视为全部授权，记录后继续（但 GATE 机制不受影响） |

### P1 — INPUT（商家输入收集）

| 属性 | 说明 |
|------|------|
| 进入条件 | P0 权限确认 + 平台选择完成 |
| 退出条件 | 至少获取：品类、店铺规模（月销/层级）、客单价、核心痛点、可提供数据清单。或商家明确声明"没有更多数据" |
| 允许操作 | 引导式提问（每次 1-3 问）、接收文件/截图/数据表格、结构化商家画像 |
| 禁止操作 | 在此阶段做分析或给建议；要求后台密码/验证码（红线）；同一问题追问超 3 次 |
| 输出物 | 商家档案（结构化 Markdown） |

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 提供了完整资料 | P1 | 结构化画像，进入 P1.5 |
| 只给了语言描述 | P1 | 结构化可用字段，标注"数据不足"维度，进入 P1.5 |
| 上传截图/数据表 | P1 | 读取并提取字段（不依赖 OCR 工具时直接描述），纳入画像 |
| 说"没有更多数据" | P1 | 标记数据缺口，明确告知"部分诊断维度将降级为领域推理"，进入 P1.5 |
| 拒绝提供成本/客单价 | P1 | 标记 R5 风险项，进入 P1.5（P5 时按 R5 审查） |
| 要求代登后台 | P1 | **立即拒绝**（红线），说明"我不会接触你的账号密码" |

### P1.5 — SELF-LEARN（自学习注入）

| 属性 | 说明 |
|------|------|
| 进入条件 | P1 商家档案完成 |
| 退出条件 | 归档检索完成，经验注入记录生成 |
| 允许操作 | 读取本地归档镜像 `archive/`、检索相似案例、提取经验 |
| 禁止操作 | 将归档中其他商家的身份/数据泄露给当前商家；在无归档时编造历史经验 |
| 输出物 | 相似案例检索结果（TOP3）+ 可借鉴经验注入当前分析 |

**检索逻辑**：按 同品类 > 同平台 > 同痛点 > 同价格带 加权匹配，取 TOP3。无归档时跳过此步，不报错。

### P2 — DIAGNOSIS（产品诊断）

| 属性 | 说明 |
|------|------|
| 进入条件 | P1.5 完成 |
| 退出条件 | 7 维度评分矩阵完成 + TOP3 问题确定 + 商家确认诊断摘要 |
| 允许操作 | WebSearch（查品类基准数据）、启动 product-diagnostician Agent、输出评分矩阵 |
| 禁止操作 | 在此阶段给优化建议；跳过商家确认直接进入下一步 |
| 确认点 | **确认点A**：展示诊断摘要（评分矩阵 + TOP3 问题），商家确认"符合实际情况"或修正 |
| 输出物 | 产品诊断报告 |

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| "符合实际情况" | P2 | 确认通过，进入 P3 |
| 修正某维度评分 | P2 | 按商家补充信息重评该维度，重出诊断摘要 |
| "跳过确认" | P2 | 跳过确认点A，进入 P3（记录"商家未确认诊断"） |

### P3 — RESEARCH（市场调研 + 竞品对标）

| 属性 | 说明 |
|------|------|
| 进入条件 | P2 诊断确认通过 |
| 退出条件 | (1) 市场调研报告完成 (2) 竞品对标矩阵（≥5 个对标对象）(3) 投流分析（如有） |
| 允许操作 | WebSearch（≥8 次）、WebFetch（竞品详情页）、web-access（按需）、并行启动 market-researcher + competitor-benchmarker（+ ad-campaign-analyst） |
| 禁止操作 | 编造竞品数据（搜索不到则标注"未检索到公开数据"）；用付费工具数据冒充自己抓取的结果；单方面依赖一个数据源 |
| 确认点 | **确认点B**：展示调研发现摘要 + 对标矩阵概览 |
| 输出物 | 市场调研报告 + 竞品对标矩阵 + 投流分析报告（可选） |

**对标对象选择**（详见 benchmark-methodology.md）：爆品（平台综合排序前 20 + 评价>500 + 好评率>95%）+ 近期销量榜前十 + 同价格带直接竞品。多渠道交叉对比：平台榜单 / 搜索引擎 / 社媒内容源。

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 确认调研发现 | P3 | 进入 P4 |
| "跳过确认" | P3 | 跳过确认点B，进入 P4 |
| 无联网权限 | P3 | 降级：只用商家提供的竞品资料 + 领域推理，标注可信度降级 |
| 某竞品搜不到公开数据 | P3 | 标注"未检索到公开数据"，用可得的替代对象 |

### P4 — DRAFT（方案草案 + 商家提问）★ GATE-1

| 属性 | 说明 |
|------|------|
| 进入条件 | P3 调研确认通过 |
| 退出条件 | 草案完成 + 商家问题清单产出 → 商家对每个问题做出回答 |
| 允许操作 | 综合诊断+调研+对标生成草案、提取 5-8 个待验证假设并转化为问题、AskUserQuestion 逐题发问 |
| 禁止操作 | 在此阶段执行具体优化操作；不展示草案就发问；跳过提问环节（此门不可跳过，即使"快速模式"） |
| 确认门 | **GATE-1（强制性，不可跳过）**：草案展示完毕 → 调出 gate-mechanism.md → 逐题发问 → 等待全部回答 |
| 输出物 | 优化方案草案 + 商家问题清单（5-8 题）+ 商家原始回答记录 |

**草案必须包含**：
- 诊断结论摘要（TOP3 问题）
- 对标结论（对标了谁、学到什么）
- 优化动作（分模块：页面/投流/内容/活动）
- 预期收益（标注可信度，不承诺具体数字）
- 资源需求（时间/预算/人力）

**问题清单要求**：
- 数量 5-8 题，每题对应一个方案成立的关键假设
- 问题要具体、可回答，不空泛（如问"客单价和成本结构"而非"介绍一下你的产品"）
- 每个问题标注用途："这个问题用于确认方案中 X 部分的可行性"

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 回答了全部问题 | P4 | 记录回答，进入 P5 |
| 只回答了部分 | P4 | 标注未答问题，追问一次；仍不答→进入 P5 按 R5 审查 |
| "跳过提问" / "快速模式" | P4 | **拒绝**：GATE-1 不可跳过，说明原因后继续逐题发问 |
| "改方案" | P4 | 回到草案，调整后重新提问 |
| "我拒绝回答这个问题" | P4 | 记录拒绝，进入 P5 按 R5 审查 |

### P5 — REVIEW（商家回答审查）★ GATE-2

| 属性 | 说明 |
|------|------|
| 进入条件 | 商家对 P4 所有问题做出回答（或明确拒绝） |
| 退出条件 | 合理性审查完成 + 通过/拒绝判定 |
| 允许操作 | 启动合理性审查流程（对照 gate-mechanism.md 的 R1-R5 标准）、输出审查报告、执行通过/拒绝判定 |
| 禁止操作 | 审查未通过时继续 P6；因商家态度强硬而妥协；接受明显不合理的回答 |
| 确认门 | **GATE-2**：审查通过 → P6 / 审查不通过 → 触发拒绝协议 → 流程终止 |
| 输出物 | 合理性审查报告 + 通过/拒绝判定 +（如拒绝）拒绝说明 |

**判定规则**（详见 gate-mechanism.md）：
- 通过：R1-R5 全部通过
- 轻微问题：个别 R1/R2 → 标注问题，要求重答，允许继续
- 严重问题：R3/R4/R5 或 ≥3 个轻微 → 触发拒绝协议，终止
- 连续 2 次不通过 → 升级话术

**分支条件表：**

| 审查结果 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 全部通过 | P5 | 进入 P6 |
| 轻微问题（重答后通过） | P5 | 进入 P6 |
| 严重问题 | P5 | 触发拒绝协议，展示拒绝说明，流程终止（商家可请求重答或缩小范围） |
| 商家要求"重新回答" | P5 | 回到 P4 重答（计 1 次审查轮次） |
| 商家选择"缩小范围" | P5 | 仅执行不依赖问题数据的模块（如竞品对标+内容优化），标记数据缺口 |
| 商家选择"结束" | P5 | 流程终止，输出已产出内容 |

### P6 — PLAN（细化执行方案）

| 属性 | 说明 |
|------|------|
| 进入条件 | P5 审查通过 |
| 退出条件 | 分模块执行方案完成（≥4 子模块：页面优化/投流/内容/活动）含时间线和优先级 |
| 允许操作 | 主 Agent 综合全部前置产出、细化每个模块的具体执行步骤 |
| 禁止操作 | 大幅偏离 P4 草案方向（只能细化不能推翻）；新增需要商家数据的步骤而不先确认 |
| 确认点 | **确认点C**：展示细化方案摘要 |
| 输出物 | 细化执行方案（含时间线/优先级/资源需求表） |

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 确认细化方案 | P6 | 进入 P7 |
| "调整某模块" | P6 | 只改该模块，重出摘要 |
| "跳过确认" | P6 | 跳过确认点C，进入 P7 |

### P7 — PRODUCTION（内容生产）

| 属性 | 说明 |
|------|------|
| 进入条件 | P6 方案确认通过 |
| 退出条件 | (1) 商品页/主图/详情页/标题优化完成 (2) 短视频脚本完成 (3) 活动方案细化完成 (4) 审查报告通过 |
| 允许操作 | 并行启动 content-optimizer + short-video-scriptwriter + promotion-planner → content-reviewer 终审 |
| 禁止操作 | 产出未通过 content-reviewer 审查的内容；使用有版权风险的素材；生成绝对化用语文案 |
| 确认点 | **确认点D**：展示内容成品摘要 + 审查结果 |
| 输出物 | 优化后商品内容 + 短视频脚本 + 细化活动方案 + 合规审查报告 |

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 确认内容成品 | P7 | 进入 P8 |
| "只要文案/只要脚本" | P7 | 只产出指定模块，跳过其他 |
| 审查发现问题 | P7 | 返回对应模块修改，重审 |
| "跳过确认" | P7 | 跳过确认点D，进入 P8 |

### P8 — ACTIVITY（配套活动策划）

| 属性 | 说明 |
|------|------|
| 进入条件 | P7 内容生产确认通过 |
| 退出条件 | 活动执行方案完成（含促销机制/平台活动匹配/时间节奏/风险预案） |
| 允许操作 | WebSearch（平台活动日历）、输出活动节奏描述、匹配平台官方活动 |
| 禁止操作 | 设计虚假促销（先提价后降价）；设计违反平台规则的优惠机制 |
| 确认点 | **确认点E**：活动方案确认 |
| 输出物 | 配套活动执行方案 |

**分支条件表：**

| 用户说/做 | 当前状态 | 执行操作 |
|----------|---------|---------|
| 确认活动方案 | P8 | 进入 P9 |
| 调整促销力度 | P8 | 重算机制，重出方案 |
| "跳过确认" | P8 | 跳过确认点E，进入 P9 |

### P9 — DELIVER（交付）

| 属性 | 说明 |
|------|------|
| 进入条件 | P8 活动方案确认通过 |
| 退出条件 | 完整优化方案包输出完毕 + 商家确认接收 |
| 允许操作 | 整合全部产出、生成执行清单、输出多格式交付物（按 deliverable-templates.md） |
| 禁止操作 | 新增内容、修改已确认内容 |
| 输出物 | 完整优化方案包（诊断+对标+方案+内容+活动+清单+确认门记录） |

### P10 — ARCHIVE（归档 + 自学习回写）

| 属性 | 说明 |
|------|------|
| 进入条件 | P9 交付完成 |
| 退出条件 | 脱敏案例生成 + 本地归档 commit + push 私人仓库（成功或明确失败已处理） |
| 允许操作 | 按 archive-self-learning.md 生成脱敏案例、扫描敏感模式、git commit + push |
| 禁止操作 | 归档含商家身份/具体经营数字/真实 URL；push 前未扫描；推送到非私人仓库 |
| 输出物 | 归档记录 + 自学习索引更新 |

**归档确认**：若商家不希望本次案例归档，P9 交付后询问一次"是否归档本次案例"，商家拒绝则跳过 push，仅本地保留脱敏记录（或完全删除）。

## 四、全局控制指令表

| 用户说 | 当前任意状态 | 执行操作 |
|--------|------------|---------|
| "暂停" | 任意 | 暂停当前流程，记录断点，询问是否继续 |
| "回到上一步" | 任意 | 回到上一状态（P0 除外），重跑该状态 |
| "换平台" | P3 之后 | 重选平台，P3 起的平台相关阶段重跑 |
| "快速模式" | 任意 | 跳过确认点 A-E；**GATE-1/GATE-2 仍强制** |
| "停止" / "到这吧" | 任意 | 立即结束，输出当前已产出内容（含已过确认门的记录） |
| "重启" | 任意 | 回到 P0 重新开始 |

## 五、续接上次会话规则

| 距上次会话 | 处理 |
|-----------|------|
| 1-7 天 | 读取上次的商家档案 + 确认门记录，从断点状态继续 |
| 7-30 天 | 读取档案，但重新确认关键数据（可能已变化） |
| 30 天以上 | 视为新会话，从 P0 重新开始（可引用旧档案作参考） |
